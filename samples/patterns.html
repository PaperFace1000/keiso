Patterns

画面の組み立てと中身の見せ方

部品を組み合わせた画面のかたまりの見本です。選んでいるものは反転して先頭に ▸ を出し、小見出しは等幅の大文字にそろえます。四隅の鉤（.k-frame）は 1 ページに 1〜2 か所だけにします。

カード

Cards

角はターミナルの丸い罫線くらいに小さく丸め、影は付けません。なぞったときは枠を濃くするだけ。状態は右上、日付や件数は下の線の下にそろえます。行き先が無くなったカードはリンクにせず、点線の枠・薄い文字・名前に取り消し線を引き、[ NOT FOUND ] と何をすればいいかを書きます。1 件も無いときはカードの代わりに置き方を 1 行で書きます。

ログインの画面

Sign in

真ん中に 1 つだけ箱を置き、四隅の鉤で囲みます。印は 48px のソリッドのアイコン。ログインに失敗したら、どちらが違うかは言わずに欄の上に ALERT の知らせを出し、何をすればいいかまで書きます。箱の中の下にパスワードを忘れたときの案内、箱の下に footer（ライセンスや稼働の状態）を、要るアプリだけ置きます。

本文

Prose

長い文は幅を 40rem に収め、行間を 1.9 にします。本文の中のリンクだけ下線を残します。箇条書きの印は小さな四角です。表は枠付きで偶数行を薄く沈め、幅が足りなければ表だけ横に動かします。脚注は線で区切った最後に置き、戻るリンクは文字で書きます。欄の中で書いたメモは小さい版（14px・1.7、見出しの線と表の縞なし）にします。

点検の記録の付け方

点検は、見る場所の順番を毎回そろえることが一番の近道です。順番が決まっていれば、見落としに気付きやすく、記録を後から読む人も迷いません。順番は見る場所の一覧にまとめてあります。

  • 温度と湿度は、入口から一番遠い棚で測る
  • 基準の外れは、数字と時刻を両方書く
  • 写真は 1 か所につき 1 枚まで
迷ったら、次の人が読んで同じ場所に立てるかを考えて書く。

記録を付け終えたら、状態を Done にします。直すことが残ったときは Review のまま担当に回します。基準の外れは、その日のうちに知らせます1。保存は Ctrl + S。

場所測るもの基準
倉庫 A温度15〜25℃
倉庫 B湿度40〜60%
空調風の強さ3 段以上
前回うまくいかなかったこと

測る棚が毎回ちがい、値を比べられなかった。

コード

Code

色分けは Shiki の CSS 変数（--shiki-*）だけを使います。どのテーマでも、文字の色は背景の上で比 4.5 以上です。上の帯に言語とコピーのボタンを置き、押すと 1.5 秒だけ「コピーした」か「コピーできなかった」に替えて元に戻します。長い行は折り返さずブロックの中だけ横に動かし、tabindex="0" でキーボードからもスクロールできるようにします（輪は内側）。

TypeScript
// 点検の項目のうち、終わった割合を返す
export function progress_of(items: readonly Item[]): number {
  const done_count = items.filter((item) => item.status === 'done').length;
  return items.length === 0 ? 0 : done_count / items.length;
}

差分

Diff

上に「+2 行 −1 行」の要約（読み上げには「2 行追加・1 行削除」の文）。足した行は SUCCESS、消した行は ALERT の色で、行の左に帯と + / − を必ず出し、色だけに頼りません。行の一部だけ変わったときは、変わった文字を塗って、足した文字に下線、消した文字に取り消し線を引きます。変わっていない行が続くところは「（変わっていない 3 行）」にまとめます。コードや設定の差分には元と新しい行番号を付けます。
